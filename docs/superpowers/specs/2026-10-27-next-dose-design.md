# 1.2.0 dose timing and availability

Approved by Dan on October 27, 2026: store optional minimum hours between doses and optional maximum quantity in a rolling 24 hours on ANMedicationConcept. Maximum uses prescribedUnit, not number of logs. Keep scheduled reminders and add separately enabled next-dose availability notifications. No automatic dosing instructions or safety guarantee. Submit 1.2.0 to TestFlight for testing; no public App Store release is authorized.

ANModelKit owns minimumHoursBetweenDoses, maximumDailyDoseAmount, and an optional nextDoseNotificationEnabled preference (legacy missing values decode as nil/off). Existing medication safety profiles retain other guardrails. Migrate dosing values only when model values are absent, persist before clearing legacy dosing values, and never move database paths. Editing must preserve unrelated medication metadata. New model fields travel through existing Codable export/import and watch sync.

One deterministic availability calculation considers doseTaken events only, ignores future events, and computes the earliest time the prescribed dose fits both constraints. A rolling window is (candidate - 24 hours, candidate]. Events with incompatible or missing dose units prevent a daily-limit calculation; do not infer a conversion. A prescribed dose larger than the maximum cannot become eligible. Missing limits/history must be explicit, not reported as medical clearance.

Each opted-in, active medication gets at most one non-repeating availability notification for a future eligible time. Do not repeat or notify immediately for past availability. Reconcile after medication/events changes, import/restore, foreground launch, and privacy changes; cancel stale notifications when disabled, archived, deleted, or indeterminate. Namespace these requests separately from scheduled reminders. Use existing medication-name privacy preference. Permission denial is visible in the opt-in UI.

Test model backwards decoding/round trips/redaction, rolling-window boundaries and sums, independent limits and combined limits, incompatible units and impossible dose, migration restart/removal, form validation, and notification replacement/cancellation/privacy. Build all shipping targets, archive/export 1.2.0 with a remote-safe build number, upload to TestFlight, add What to Test notes and existing beta groups, then verify processing/distribution status. Physical-device upgrade and notification delivery remain required beta verification if no device is available locally.
