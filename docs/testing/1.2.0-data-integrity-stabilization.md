# 1.2.0 data integrity and upgrade stabilization

October 27, 2026. Bug fixes only; no screen, navigation, onboarding or feature changes.

Final automated verification: **779 passed, zero failed, zero skipped, 67 suites**
on an isolated iPhone 17 simulator with iOS 26.5 and Xcode 27.2 RC. The actual
result bundle confirms these counts. This completes the automated data/upgrade
pass; it does not close the release gates listed below.

## Reproduced defects and corrections

| Issue | Evidence before correction | Correction |
| --- | --- | --- |
| Legacy `.sqlite`, `.db` and extensionless databases read as empty | Real SQLite fixtures returned no medication IDs/quantities and created a neighboring `.sqlite3` database. Corrupt `.db` files also returned an empty result rather than an error. The same reader exists in the 1.1.2 source. | Read a disposable copy of the discovered database and its WAL/SHM sidecars using Bodega's required `.sqlite3` filename. Preserve originals until successful verification and archival. |
| An older empty neighbor hides the actual legacy database | Reproducing the old reader's empty `.sqlite3` neighbor prevented recovery of each nonstandard legacy format. | When the preferred flat `.sqlite3` is empty, check its legacy neighbors and carry the actual recovered source through verification and archival. The choice among populated legacy source files is unchanged. |
| Recovered legacy data reverts newer active records | A divergent-record upgrade reproduced quantity reverting from 30 to 192 and loss of a newer nickname/interval. Same-ID historical events are exposed to the same legacy-first overwrite. | Preserve complete current medications/events for matching IDs and recover missing IDs. Skip writes to existing IDs instead of deleting/reinserting them. Keep legacy archives for recovery. |
| Replacing records resets preferences even when keeping settings | Settings regressions failed for haptics, font and the device's automatic backup bookmark. The 1.1.2 import also calls `clearAllData()`. | Replace records through `clearUserData()`. Apply imported preferences only when requested, preserving device-specific backup access. |
| History reassigned between medications with identical names | Two medications with different IDs and identical names imported an event under the first medication's ID. | Resolve exact persisted medication IDs first; allow a name fallback only when unambiguous. |
| History-only merge drops valid events | An event referencing an existing medication was skipped because that medication was absent from the import's medication array. | Resolve against persisted medications, including existing records when merging. |
| A skipped duplicate can incorrectly validate missing history references | Independent review identified a merge where preflight accepted a stale imported medication name, but insertion retained the current name and silently dropped the event. A regression reproduced it. | Construct preflight's effective medication set with the same precedence as insertion, and share the exact-ID/unique-name resolver. |
| Invalid replacement imports silently delete existing records | An unresolved event reference returned success after removing the existing medication and history. Ambiguous references also returned success after skipping history. | Validate reference resolution before replacing any records; reject unresolved or ambiguous files through the existing invalid-format error. |
| Storage metadata has no reset classification | The production constants failed the exactly-one-category contract for schema version and both archived legacy paths. | Explicitly preserve these device-specific recovery keys during settings reset. Existing reset behavior already left them untouched; this makes that safety policy explicit and covered. |
| Migration backups collide within one second | A fixed-clock regression failed on its second backup; its directory already contained the first snapshot. | Add a unique suffix while retaining the existing directory prefix and timestamp. Existing backups remain discoverable. |
| Restore continues without its safety backup | A blocked backup directory reproduced current records being replaced despite a failed pre-restore backup. | Stop before replacement and report the error. |
| Empty backups report a successful restore | An empty directory returned success without restoring records. | Require at least one database before starting recovery. |
| Retention cleanup deletes the selected restore source | Restoring the oldest of five retained backups created a sixth safety backup, deleted the selected source, then returned success with the wrong records. | Stage the requested databases and sidecars before creating the safety backup and running retention cleanup. |
| Older logging sheets reset quantity and newer metadata | Detail, list and quick-log regressions all retained two dose events but lost one fractional stock deduction and overwrote a later nickname edit. The stale-value assignments also exist in 1.1.2. | Resolve the latest medication by ID before calculating quantity or creating the event's medication snapshot. |
| Older logging sheets recreate deleted medications | All three logging paths recreated a medication and history after the original record was deleted. | Reject logging when the medication ID is no longer present; detail uses the existing error message surface. |

## Reliable test fixtures

The old migration suite seeded `test_legacy_medications` and `test_migration_medications`, which the production migrator never discovers or writes. Several assertions inspected stores before awaiting initial loading. Another test changed permissions on the entire shared container. These fixtures could not establish safe upgrade behavior.

Migration now accepts injectable directories/defaults, with unchanged production defaults. Tests use unique disposable directories and production filenames, await database loading, and exercise discovery → merge → verification → archival. Coverage includes fresh/current-only/legacy/mixed stores, all discovered flat extensions, medication/event IDs, notes, fractional doses, failed writes and retry, corrupt source preservation, dry run, 1,000 records, and later quantity edits surviving repeated migration instances.

The WAL fixture uses SQLite only to configure journaling and hold a read snapshot; Boutique writes the medication records. Assertions prove the new ID is present in a nonempty WAL, absent from a main-file-only control, recovered by the full copy, and left intact in the original WAL. An idle connection alone did not prevent checkpointing; that fixture failed its control assertions and was corrected before counting the result.

The DataStore suite's identifier was not actually sharing medication/event databases: its initializer already appends a UUID. Shared selection defaults/navigation remained a source of interference. The suite is serialized, and its previously disabled selection cleanup test is re-enabled.

The migration backup restore fixture now closes fixture stores before copying/replacing database files and reopens fresh stores to verify persisted contents. Its previous assertions read stale Boutique caches. This verifies offline migration recovery, not live cache refresh. The shipping automatic-backup restore UI uses JSON import through `AutomaticBackupManager`, a separate path.

## Verification and remaining release gates

- Initial reproduced failures are retained in local result bundles, outside Git.
- Initial focused upgrade/import verification passed: 27 tests across four suites on iOS Simulator 26.5 with Xcode 27.2 RC.
- Storage/reset verification passed: 37 tests across four suites, including the re-enabled selection cleanup case. This precedes the additional retention regression and is not a final combined count.
- Combined data/upgrade verification passed: **109 tests in 11 suites**, including all four backup regressions, restore integrity and the full export/clear/import flow. The workflow fixture now explicitly confirms the existing settings choice before expecting records to be restored.
- Stock and existing daily-flow verification passed: **63 tests in four suites**, including all three stale-snapshot/deleted-medication paths, detail/list logging, History edits/deletes and quick-log Undo. These are disjoint from the 109-test data set; the final full run below supersedes intermediate counts.
- Review follow-up verification passed: **17 tests in three suites** covering exact-file reads/WAL recovery, empty-neighbor recovery, upgrade/restart scenarios and import reference validation. These overlap the earlier data set and must not be added to it as independent coverage.
- The first full plan completed with **775 passed, zero failed, three skipped** (778 total; 67 suites). The skipped import tests used invalid placeholder UUIDs and were disabled before stabilization. They now use valid typed fixtures, are re-enabled, and assert safe reference repair or rejection without losing existing records.
- The final full plan completed with **779 passed, zero failed, zero skipped**, in 67 suites, after the current-record preservation fix. An isolated AsNeeded-only simulator was used after intermittent XCTest launch stalls on the existing simulator. The final command exited successfully, and `xcresulttool` independently reported `Passed`, 779 passed, zero failed and zero skipped. The older incomplete/duplicate-invocation attempts are not counted. A legacy notification test required declining the simulator's system permission dialog; this is an interactive test-suite limitation, not physical delivery evidence.
- The optimized DataStore script emitted a formatter error and then a success banner. That contradictory banner is not counted as verification; raw test output is used.
- No production database path, persisted model schema, primary store filename or container changed. Conflict precedence deliberately changes to preserve current same-ID records; the independent review and regression explain why. Richer legacy metadata remains archived rather than guessed into an active record. Missing-ID recovery still has no historical deletion tombstones, so intentionally deleted records cannot be distinguished from orphaned ones.
- Physical-device upgrade and restart checks on the final candidate remain required. These unit fixtures do not establish that a real 1.1.2 installation has been upgraded on hardware.
- Separate event/stock writes and interruption/write-failure recovery across stores remain open, including JSON import rollback after a storage failure. Rejecting malformed references before import does not establish atomic replacement. Paired Watch/widget transport, notification delivery/privacy and the remaining continuity/accessibility checklist also remain open. Do not sign off the release from these results alone.
