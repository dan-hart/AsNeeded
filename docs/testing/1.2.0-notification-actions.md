# 1.2.0 Notification Dose-Form Navigation

October 28, 2026, `task/v1.2.0`.

## Intended behavior

The maintainer clarified that the notification's **Log** action should open the app to the dose form for the medication named by that notification. It must not record a dose until the person confirms in the form.

Log, previously delivered `TAKEN_ACTION` buttons, and notification body taps now all use the app's existing `navigateToLogDose` path. This replaces the separate notification quick-save queue and removes its automatic dose/stock mutations and generated event IDs. The ordinary in-app quick-log behavior is unchanged.

- Both scheduled reminders and next-dose notifications offer Log with foreground activation.
- The notification carries a medication UUID; the current committed medication is resolved after storage is ready. No last-used-medication fallback is allowed.
- Form presentation waits for the scene to be active and existing sheets to be dismissed. Repeated taps for an already-open medication keep that form instead of stacking another.
- Missing or archived targets show an unavailable message.
- Skip dismisses only the delivered occurrence and does not cancel a recurring schedule or record a dose.
- The app delegate registers the response handler/categories at launch, independently of migration/reconciliation. Existing notification-name privacy settings remain in effect.

No storage paths, schema, defaults keys, package dependencies or medication models changed. Critical Alerts remain pending Apple's separate approval and are not enabled by this change.

## Verification

Full simulator regression suite: **928 tests passed, zero failures or skips**, on iPhone 17 / iOS 26.5. The optimized parallel script used two workers. Its formatter emitted contradictory generic status, so the authoritative xcresult summary was inspected directly and confirmed all 928 tests passed.

Focused tests cover notification category labels/foreground behavior; Log, legacy Mark as Taken, and body-tap routing; cold-store resolution of the exact medication; unchanged doses/stock before confirmation; stale chooser/widget/detail destinations; missing and archived targets; malformed responses; Skip dismissal; and exposure of the actual Objective-C notification-response delegate selector. Obsolete automatic-save notification tests were replaced with the clarified review-first contract. Existing dose-save, Undo, quick-log, widget-navigation and storage coverage remains in the full suite.

Code review found no further actionable routing defects. Native operating-system notification action expansion was not reliably automated on the synthetic simulator; end-to-end tapping Log on a physical notification remains a manual check. A launch/install receipt establishes delivery, not that this system interaction passed.

The signed Release device build passed deep/strict signature verification and was installed in place on dip17pm as 1.2.0 (318). CoreDevice confirmed the installed app. Its initial launch attempt was blocked because the phone was locked; a later successful launch, if performed, is a separate delivery check and does not establish that a real notification action was manually tested.
