# 1.2.0 Notification Action Repair

October 28, 2026, `task/v1.2.0`.

## Defect and repair

The app registered notification categories with “Mark as Taken” and “Skip” buttons, but its application delegate did not implement or register a `UNUserNotificationCenterDelegate`. Notification responses therefore never reached dose logging or app navigation.

The app now registers its delegate and categories at launch, independently of migration/notification reconciliation. “Log” foregrounds the app and queues the exact medication until the Medication screen is active, storage is ready, and existing sheets are dismissed. It uses the existing quick-log path, prescribed/default dose, atomic dose/stock transaction, guidance feedback, four-second confirmation and Undo. It does not write medication data from the notification callback.

- Both scheduled reminders and next-dose notifications offer Log.
- Previously delivered `TAKEN_ACTION` responses remain supported.
- Tapping a notification body opens that medication's dose form without recording a dose.
- Skip dismisses only the delivered occurrence; recurring schedules remain intact and no dose is recorded.
- Missing/archived targets show an unavailable message; they never fall back to another medication.
- Save failures show the existing error alert without a false success confirmation.
- Each delivered occurrence derives a stable event ID from the request identity, medication ID and delivery date. Replays use the existing transaction's idempotency; different recurring deliveries receive different IDs. Replayed committed doses can finish interrupted reminder cleanup without replacing newer Undo feedback.
- Foreground notifications use native banner/list/sound presentation. Existing notification-name privacy preferences remain in effect.

Review also found and repaired cancellation handling: an interrupted save retains its queued action for foreground retry, including when persistence translates cancellation into a recovery error. The cancellation regression failed before the fix and passed afterward.

No storage paths, schema, defaults keys, product dependencies or medication models changed.

## Verification

The new regression suite failed before implementation because the action/response handling was absent. The final full app suite passed **929 tests, zero failures**, on iPhone 17 / iOS 26.5 Simulator, using the optimized parallel script with two workers. The authoritative xcresult summary was inspected after the script completed.

The seven new tests cover category titles/foreground options, legacy identifiers, malformed/foreign responses, recurring occurrence identity, cold-store logging of the exact medication/amount/time, stock changes, replay after restart, reminder cleanup, Undo, default navigation without logging, deleted/archived targets, atomic failure/retry, cancellation during commit/recovery, and queued dispatch/Skip. Existing scheduled-reminder and quick-log Undo regression suites also pass. No purchases, real medication records or personal-device notification settings were changed.

A dedicated synthetic simulator displayed a delivered reminder in Notification Center after permission was enabled through the app. Native quick-action expansion could not be completed reliably through the simulator automation, so tapping the operating system's Log and Skip buttons end to end is **not claimed as manually verified**. Before release, confirm on a device: scheduled and next-dose Log, body-tap review, Skip with a recurring reminder, cold launch, confirmation/Undo, and logging while another sheet is open. No physical-device install or TestFlight upload was performed for this revision.
