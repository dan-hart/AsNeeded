# 1.2.0 Widget Experience Verification

Date: October 28, 2026. Branch: `task/v1.2.0`.

## Scope

Maintainer-requested widget improvements after the release conflict/regression work. Existing widget kind identifiers remain available. Medication widgets use native medication selection and Show Names configuration; the primary kind supports small, medium and large sizes. Usage widgets summarize seven complete local days ending yesterday, with a count-only fallback when quantities cannot be combined safely. Lock Screen families open the exact medication's dose form.

Home Screen links open details, a dose form, History or scoped Trends. They never record a dose. The retained cached logging intent foregrounds the app and queues the exact dose form; extension execution fails closed. Missing or archived widget targets show unavailable instead of selecting another medication. Widget Trends scope does not overwrite saved tab filters. Normal archived History access remains available.

The existing data paths, schema, medication identifiers, transaction persistence and dose/stock safeguards are unchanged. Committed snapshots and guidance-profile changes invalidate widgets; repeated unchanged snapshots are deduplicated. One existing haptics suite now uses isolated preferences, and the medication deletion test observes completion with a bounded deadline instead of assuming disk writes finish within 100 milliseconds.

## Automated coverage

The added projection, routing, navigation, refresh and cached-intent tests cover:

- Exact UUID selection, missing/archived targets, stale commands and already-mounted History.
- Local complete-day/DST boundaries, invalid/mixed quantities and units, comparison periods and timeline boundaries.
- Temporary Trends selection/range with saved preferences preserved.
- Committed changes, rollback, unchanged snapshots and profile-only updates.
- Actual cached intent `perform()` navigation, malformed identity and no dose/stock mutation.

Full app suite: **922 tests passed, zero failures** on iOS 26.5, iPhone 17 simulator. The final run includes the legacy foreground intent fix and the bounded deletion-test wait. Evidence: `/tmp/AsNeeded-widget-verified.xcresult`, inspected with `xcresulttool get test-results summary`.

An earlier full run exposed the deletion test's fixed-delay assumption (921 passed, one failed); that test was corrected and the full suite rerun. An earlier run also exposed shared haptics preferences; those tests now use isolated settings. These failures are not hidden by test retries.

The five scanner/dependency Python suites passed **29 checks**. The standalone watch availability harness passed **three checks**. The app and widget extension built for the simulator; the project plist and `git diff --check` passed. Spec and code-quality reviews were completed and valid navigation/refresh findings fixed. The final foreground intent adjustment also received code review.

## Manual evidence

A dedicated fresh iOS 26.5 iPhone 17 simulator contains only synthetic `Example Relief` data. No personal medication data was used or captured.

- Installed the pre-change static-widget app, placed its small widget, and upgraded in place. The existing kind continued rendering with the new implementation.
- Opened native Edit Widget and selected the synthetic medication.
- Turned Show Names off and verified the Home Screen rendered generic `Medication` text.
- Tapped that widget and verified it opened the exact synthetic medication detail screen without recording a dose.
- Inspected Medication and Usage gallery sizes and the installed empty-history state.
- Inspected dark appearance with the largest accessibility text setting; the installed widgets remained readable without overlapping text.

Screenshots were kept outside Git. The gallery captures precede the final richer synthetic gallery sample; they establish rendering, not final sample contents. Native resize controls were inspected, but a successful resize retaining configuration was not established in this session.

## Remaining device verification

Before release, check physical-device Lock Screen inline/circular/rectangular rendering, Always On/privacy redaction, tinted rendering, actual cached pre-upgrade intent dispatch to the foreground app, resizing/configuration continuity, two independently configured instances, and refresh after a real app-recorded dose. Unit tests establish routing/persistence contracts, not the operating system's cached-widget dispatch behavior. No physical-phone install or TestFlight upload was performed for this widget revision.
