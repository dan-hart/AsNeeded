## Corrections

- Undo captures the exact event, rejects overlapping Undo for that event, preserves a newer confirmation, and remains retryable after failure. Confirmation sequencing also prevents a late reminder acknowledgement from replacing a newer dose confirmation.
- Automatic backups move provider work off the main actor, clear cancelled setup, serialize writes, and coalesce changes arriving during a backup into a subsequent backup. Folder changes cannot report an older folder's success. Validation retries reuse the captured export bytes, retaining the selected privacy/settings options.
- Ordinary scheduled reminders use stable identifiers, normalize calendar components, preserve existing requests when inventory/replacement fails, and serialize removal against in-flight scheduling. Legacy-to-canonical cancellation aliases prevent a stale screen from leaving a replacement reminder behind. Dose acknowledgements and removed-medication cleanup run after persistence commits.
- History and Trends replace periodic polling with committed snapshots and cached calculations. Foreground, calendar-day, timezone and significant-clock changes refresh the appropriate state. UI observers never receive intermediate event/stock transaction writes.
- The Medication tab has the requested floating Log Dose button with reserved list clearance. Multiple medications open the existing chooser at medium height, expandable to large; one medication retains the direct dose-form path.

These are selective adaptations, not a merge of the divergent development branch. No urgency preferences, new Trends capabilities, sync platform, or design framework was introduced. Storage locations, schema and existing unit rules remain unchanged.
