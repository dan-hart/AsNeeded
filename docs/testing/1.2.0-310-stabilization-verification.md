# 1.2.0 (310) atomic persistence verification

October 28, 2026. Scope: repair dose/stock saves and import rollback, remove Live Activities, and verify an in-place iPhone upgrade. No new product features or navigation changes.

## Corrections

- Dose recording, stock adjustment, history edits/deletes and Undo share one persistence owner. It loads fresh records under an app/widget file lock and records a durable undo journal before changing either SQLite store.
- Failures restore both stores. Interrupted saves and failed rollback retain recovery metadata; startup and subsequent access recover before proceeding. Invalid journals are retained and access fails closed.
- Imports preflight references, then protect records and exactly the persisted imported preferences in the same recovery operation. Unrelated preference edits and registered fallbacks are preserved. Widgets require app recovery when an interrupted import owns app-only preferences.
- Same-event retries do not deduct twice. Watch delivery carries stable retry identity/time; older payloads remain readable. Medication editing preserves stock consumed while an unchanged-quantity editor was open.
- Live Activity creation, updates, rendering configuration, support key and obsolete tests are removed. Only the old attribute decoding shape remains in the app to end previously active activities at launch. Ordinary widgets and notifications remain.
- Primary database names, App Group, model schema and existing migration source archives are unchanged.

## Automated evidence

The full unit plan on an isolated iPhone 17 simulator, iOS 26.5, passed **786 tests, zero failures, zero skips**. Result bundle: `/tmp/asneeded-310-final.xcresult`. The preceding test-isolation failure was caused by a registration-domain fallback left by a new regression test; restoring that domain resolves it without weakening the existing haptics assertion.

On the attached iPhone SE (2nd generation), iOS 26.7.2, **34 tests in four suites passed, zero failures/skips**: `AtomicPersistenceTests`, `DataMigrationManagerTests`, `LegacyDatabaseReadTests`, `WatchMessageValidationTests`. Result bundle: `/tmp/asneeded-310-device-tests.xcresult`.

Atomic hardware fixtures use uniquely owned children of the real App Group and isolated defaults, never the user's primary databases. The legacy-upgrade fixture migrates real Boutique legacy files twice, preserves IDs/fractional stock/history notes/no alert opt-in, interrupts a dose save, reopens storage, verifies recovery, then retries the same dose twice and proves one deduction. Other cases cover partial imports, exact preference rollback, concurrent writers, mismatched units, corrupt journals, failed rollback and stale editors.

Before the install, the phone reported 1.2.0 (309). Existing preferences were backed up privately outside Git. After the test install, no preference keys were removed; shared preferences were unchanged. Only app-use counters/timestamps and StoreKit check timestamps changed. The file-inventory tool did not expose the live database files despite the app displaying saved records, so that inventory is not used as evidence of database emptiness or recovery state. Fixture cleanup and journal removal are asserted by the hardware tests.

## Installed Release candidate

The Release configuration compiled successfully, and `codesign --verify --deep --strict` passed. The app, widget and Watch bundles all report 1.2.0 (310), with no Live Activities support key. The signed Release app was installed in place and launched twice with termination between launches. Both foreground accessibility reads showed the familiar medication list and four tabs. The same medication labels, quantity, last-dose text and saved-limit summary were present across the restart (tree ordering/timing differed). No dose was logged or user record edited by these checks. Final installed-app metadata confirms 1.2.0 (310).

The final preference comparison again found no removed/added keys, unchanged shared preferences, and only the expected app-use/StoreKit timestamp changes. Private UI dumps, backups, logs and artifacts remain outside Git; no medication names or personal device identifiers are included here.

## Upgrade scope and release limits

This is an actual 309-to-310 install plus synthetic legacy-data/recovery validation on hardware. The phone already ran 1.2.0, so this is not evidence of upgrading a populated public 1.1.2 binary. No downgrade or app deletion was performed. Process-interruption fault coverage does not certify every power-loss/filesystem failure. Live Activity retirement runs on launch; dismissal of an already-running real activity remains a separate hands-on scenario when one exists.

Public-version visual continuity, full assistive-technology operation, real paired Watch transport, notification delivery/privacy, and final TestFlight distribution remain separate release gates. No public release or TestFlight upload is part of this verification receipt.
