# 1.2.0 dose timing verification

## Scope

Optional minimum interval and maximum quantity in a rolling 24 hours on ANModelKit medication records; persisted profile migration; visible app/Shortcut/watch guidance; separately enabled next-dose availability notifications alongside scheduled reminders.

## Verified during implementation

- ANModelKit: 53 Swift Testing tests pass, including legacy decoding, round trips, redaction and independent optional fields. App pins revision `ee9eb9e1603f1832cace9dea4a5fa07247d5de51`.
- Shared timing regression harness: 10 tests pass against actual app service/model sources, including quantity sums, exact rolling boundary, both limits, unrelated/future/non-dose filtering, unknown units, impossible dose, model precedence, custom-unit logging and decimal rounding.
- Watch model harness: 3 tests pass; reproducible with `scripts/tests/watch-medication-availability.test.sh`.
- First integrated simulator run: 67 tests in 8 relevant suites pass. Final expanded simulator verification: **111 tests in 12 suites pass** on iPhone 17 / iOS 26.5, including detail logging, Shortcut selection and watch/trends payload regressions.
- Repository scripts now propagate xcodebuild failures through xcsift and accept simulator/worker overrides.

## Broader test-suite limitations

The complete parallel script was run and exposed a crash in legacy migration test setup. The legacy suite shares database paths and temporarily removes App Group write permissions while other tests run. Tests are now serialized, permission restoration is deferred, and setup throws rather than force-unwrapping a failed storage engine. Re-running that suite yields 8 passes and 7 failures without a crash.

The remaining failures involve unchanged fixture paths (`test_legacy_medications` and `test_migration_medications` versus production discovery/storage names) and a simulator directory-permission assumption. They were not hidden or rewritten as part of this feature.

A separate broader run found unchanged tests asserting restored raw-database contents through stale Boutique caches, a settings-import flow that never confirms its required settings-choice dialog, and three existing migration UserDefaults keys missing the tested reset classification. The notification authorization test requests real system permission and waits for interaction, so the broader run was stopped at that prompt. Owning source/tests were compared to the branch base, but an untouched baseline build was not executed. The full suite is therefore not reported as green.

## Release dependency compatibility

RevenueCat 5.37.0 fails to compile with the installed Xcode 27.2 compiler due to a synthesized initializer collision. Exact version 5.78.0 includes the upstream Xcode 27 fix (RevenueCat PR #6949). No private dependency-cache patches are used.
