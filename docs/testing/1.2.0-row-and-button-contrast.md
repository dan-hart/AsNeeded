# Medication row and button contrast stabilization

October 28, 2026. Follow-up to TestFlight 1.2.0 (311); these edits are not in that distributed artifact.

## Corrections

- Removed medication-row status badges (including Limits met, Review/Caution/Waiting) and the warning/limits headline. The row keeps last-dose text and a configured future next-dose window as neutral timing text. Its accessibility container no longer injects the removed warning/limits summary; visible timing remains accessible. Dose assessment, limits, notifications, dose-form guidance and persistence behavior are unchanged.
- Primary Log/Save actions use the app accent, keeping medication colors on identity visuals and appearance choices. Filled action backgrounds are opaque, rather than mixing their color with the surface through translucent gradient endpoints. This fixes the red/black row action without changing the medication's saved color.
- Corrected fixed-white labels in reminder selections/actions, onboarding, empty states, backup/restore actions, support/feedback buttons and glyphs, plus the small-widget and Watch action labels. Appearance picker swatches keep per-color contrast. Custom destructive settings rows retain their red icon and explicit wording with a primary-color title. Loading feedback uses an opaque semantic surface with primary text.
- The shared foreground View helper now reads the actual SwiftUI appearance by default and applies that foreground to an embedded progress indicator's tint. Explicit appearance overrides remain supported.
- Slightly adjusted the light/dark accent shades for normal-text contrast on native system surfaces. Populated the previously empty widget accent asset with the same palette used by the app and Watch. Opaque filled actions measure **5.054:1** (white/light accent) and **7.005:1** (black/dark accent), independently calculated from the sRGB asset values. This is distinct from measuring every rendered antialiased pixel.

## Coverage

Source-reviewed button styles across iOS app screens/components, widgets and Watch. Added regressions for the app accent's foreground and accent-colored text on six native background surfaces in each appearance. Existing tests independently check black/white selection across the medication palette. Tests deliberately exercise the color behavior; no snapshot/UI test dependency was introduced.

The optimized parallel script passed the 10 focused contrast tests in its result bundle, although its quiet-output formatter emitted an erroneous no-output diagnostic. Full parallel runs exposed shared UserDefaults interference in persistence/settings tests (4 then 5 failures). The serial full-plan run passed **794 tests, zero failures/skips**. No assertions were weakened or storage code changed to accommodate parallel execution. Final source verification is recorded separately below.

Manually inspected synthetic medication rows and the Log Dose sheet on an iPhone SE (3rd generation) simulator, iOS 26.5: light appearance, large accessibility text, dark appearance, and Increase Contrast. The compact row now has no status badge or warning headline; controls remain tappable. The dose sheet's sticky action has white text in light appearance and black text on the lighter accent in dark appearance. This is selected-surface simulator evidence, not a physical Watch/widget, every button-state combination or complete VoiceOver certification.

Temporary screenshots, raw UI captures, test results and logs are outside Git under `/tmp/asneeded-button-*`. The previously installed/uploaded build 311 is unchanged; this task does not perform another device install or beta upload.

## References

[Apple buttons guidance](https://developer.apple.com/design/human-interface-guidelines/buttons) and [W3C normal-text contrast guidance](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) support the native action treatment and 4.5:1 normal-text target. Disabled controls are excluded from the normal-text contrast requirement; active and selected labels remain in scope.
