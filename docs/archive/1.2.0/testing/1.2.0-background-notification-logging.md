# Background notification Log

The maintainer explicitly authorized this change after the earlier review-first behavior.

## Behavior

- **Log** saves the medication's current prescribed dose in the background. The action requires authentication when iOS requires unlocking, but does not request foreground activation.
- An ordinary notification body tap opens the medication's dose form without saving.
- A quiet **Dose logged** local notification confirms a durable save. Its body and **View Log** action open filtered History without saving again.
- Missing/archived medication, absent amount/unit, invalid quantities, caution/warning guidance, and unready storage leave the dose unchanged and produce **Dose not logged** feedback. Its body and **Review Dose** open the dose form.
- Confirmation names follow the existing notification-name privacy preference. Hidden-name and failure feedback remain generic. Feedback has no sound and respects system notification/Focus settings; iOS controls whether a banner is shown.
- Feedback delivery failure is logged separately and never turns an already committed dose into a reported save failure. A retry replaces earlier feedback for the same occurrence.
- No new toast or background Undo interface was added. Existing in-app confirmation/Undo remains unchanged.

## Data integrity

The existing journaled DataStore save now has an internal event-builder overload. The public API is unchanged. Notification target, prescribed amount/unit, guidance, and logging time are resolved inside the existing transaction lock. Both stock and event, recording-order preferences, reminder acknowledgement, availability refresh, and backup effects retain their existing owner.

A deterministic event UUID includes category, request identifier, medication UUID and delivery date. Replaying an occurrence preserves its original event/dose/date, including after a prescription change or archival. Recurring deliveries get separate identities. A competing action assesses history only after previous commits; it cannot bypass an interval using a stale pre-lock snapshot or timestamp.

No data paths, filenames, containers, schema, decoding, migration source rules or persisted settings keys changed. Existing journal recovery handles rollback/interruption. A failed or concurrently running startup migration fails the action visibly instead of scheduling an unexpected save later. Deleted medications' feedback is included in notification artifact cleanup.

- **30 focused tests passed** across action parsing, exact routing, main-thread asynchronous completion, cold-store logging, current prescriptions, replay, overlapping occurrences, missing details, guidance, rollback, recording order, privacy, feedback failure/replacement, cleanup, and existing reminder reliability.
- **940 tests passed, zero failures or skips**, in the complete regression suite. Authoritative result: `Test-AsNeeded-2026.10.29_10-48-03--0500.xcresult`.
- Independent review found and verified a fix for stale failure feedback surviving a successful retry. Final review found no actionable defects.
- Injected notification clients avoid permission prompts and changes to real reminders during tests. Real Lock Screen action delivery, authentication and banner presentation remain physical-device checks.
