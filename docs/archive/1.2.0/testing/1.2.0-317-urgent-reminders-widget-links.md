# 1.2.0 urgent reminders and Lock Screen dose links

Authorized October 28, 2026 as two explicit additions to the release freeze. Adapted the existing work from `f24ace8`, `d408e1d`, `6e48d4b`, the subsequent urgency rollback hardening, and `17e2447`; no divergent branch was merged. Existing stabilization changes remain intact.

## Behavior and storage

- Each medication detail has an Urgent Reminders toggle under Scheduled Reminders. It controls Time Sensitive delivery for existing and future scheduled reminders for that medication. Next-dose availability alerts retain ordinary priority. The UI refreshes iOS delivery status on foreground and explains disabled/unavailable delivery.
- New settings default to ordinary delivery. On reconciliation after storage is ready, existing scheduled reminders seed an absent preference from their actual delivery level; ordinary reminders are never automatically promoted. Notification names/privacy, identifiers and schedules survive priority changes.
- Priority changes serialize with reminder creation, cancellation and medication removal. Preference persistence follows accepted replacements; failures restore earlier replacements when possible and present an error. Concurrent deletion invalidates suspended changes and prevents rollback from resurrecting removed notifications. If the OS also rejects rollback, later reconciliation retries the saved preference; an OS notification API sequence cannot provide a database-style atomic transaction.
- The adapted urgency store verifies its writes and preserves corrupt data rather than replacing it. A typed `medicationNotificationUrgency` key is device-local, classified for reset/removal and excluded from exports. No medication model schema, database location, existing settings key or dependency revision changed. Medication removal cleans the corresponding preference after the existing data commit.
- Time Sensitive capability is enabled for the iOS app. App and provisioning-profile entitlement flags were both verified as true on the signed Release candidate. This uses [Apple's Time Sensitive notification level](https://developer.apple.com/documentation/usernotifications/unnotificationinterruptionlevel/timesensitive), subject to the user's system settings; it does not bypass the silent switch like a Critical Alert.
- Circular, rectangular and inline Lock Screen widgets use the existing `asneeded://log/<UUID>` route for their displayed medication. Empty entries provide no medication-specific URL. Opening the link presents the existing dose form and records nothing automatically.
- The app waits for a stable medication snapshot and validates the exact active identity. Unknown, invalid and archived identities cannot select another medication. Pending links wait while the root list already owns an editing/picker/dose sheet. A warm link from another medication detail reveals the root list before presenting the linked form. Storage failures retain the pending identity for a foreground retry.
