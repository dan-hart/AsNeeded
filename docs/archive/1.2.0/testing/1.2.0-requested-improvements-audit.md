# Requested 1.2.0 improvements audit

October 28, 2026. Working branch: `task/v1.2.0`. The maintainer explicitly authorized the complete list below, including the History chooser, shared quick-log guidance and expanded Trends presentation. These are scoped additions to the freeze; Mac/iCloud sync, ANDesignKit and other deferred work remain separate.

| Requested improvement | Result and owning implementation |
| --- | --- |
| Quick-log Undo races | Present. `MedicationListViewModel` captures the exact event ID, serializes repeated Undo for that event, preserves newer confirmations and ignores late confirmation completions. Four suspended-operation regressions cover the behavior. |
| Backup freezes and cancellation | Present. Backup provider work runs off the main actor; privacy/picker cancellation clears setup; active backups serialize and coalesce later changes. Folder/configuration changes cannot publish stale success. `AutomaticBackupStabilizationTests` covers cancellation, overlap and recovery. |
| Backup progress visibility | Present. `AutomaticBackupViewModel` forwards manager changes, and the Backup Now UI displays the running state. Suspended-provider tests verify busy state remains observable until completion. |
| Scheduled-reminder reliability | Present. Reconciliation preserves requests until replacements succeed; atomic dose commits acknowledge delivered reminders; removal generations prevent suspended adds from resurrecting deleted medications' notifications. Fake notification clients and isolated defaults cover races and failure paths. |
| Faster History and Trends | Present before this audit. Both view models subscribe to committed snapshots and cache derived results. No 0.5-second History or 2-second Trends polling loop remains. Calendar/timezone/foreground changes invalidate relevant derived state. |
| Consistent quick-log controls | Added. Medication rows, picker rows and selected-medication History actions share `DoseLogPressGestureModifier`, deterministic `DoseLogPressState`, progress rings and haptic behavior. Movement/disappearance cancels a pending hold; a completed threshold saves once while repeated holds are blocked during the save. Native accessibility actions remain available. Shared dismissible hints retire across tabs after discovery, dismissal or three impressions. |
| Settings scrolling fixes | Added. `VerticalOnlyScrollView` pins content to the viewport across Settings, Support and disclaimer screens. Existing wrapping typography and accessibility layout remain. |
| Build reliability | Added. Removed private `DHUtilityKit` from source imports, project and resolution pins. Local `SecretManager` handles missing, blank, placeholder and configured values; RevenueCat callers guard unconfigured SDK access. Optional local secrets stay ignored. Release-key checks detect unintentionally keyless archives. A clean-checkout simulator-build workflow targets the release branch and verifies key propagation without logging values. |
| History All Log Dose chooser | Added. All view opens the shared searchable half-sheet. Selection is revalidated after dismissal and opens the retained dose form. A hold uses the existing atomic quick-log/Undo coordinator. Archived records are excluded. |
| Chart-first Trends, 90 days and complete days | Added. Visualization precedes controls and statistics; ranges include 14/30/90 days. Daily metrics and calendar buckets use complete calendar days ending yesterday, including DST and timezone changes. UI copy states the boundary. Current medication stock, dose availability and shared refill guidance retain their existing live semantics. |
| Per-medication urgent reminder settings | Present. Each medication controls Time Sensitive priority for its scheduled reminders; actual existing priority is preserved during upgrade. Availability alerts remain ordinary priority. Rollback/removal and persisted preference tests remain green. |
| Lock Screen widget dose links | Present. All three accessory widget families link to the displayed active medication's dose form. Cold and warm routing waits for stable data, checks identity and does not log automatically. |
